Guía del diagrama

Los 10 puntos de la arquitectura

Explicación de cada bloque numerado en el gráfico de referencia.

  1. 1

    Fuentes de Datos

    Punto de partida: sistemas corporativos (ERP, WMS, CRM, Finanzas, RRHH), bases operacionales (Oracle, SQL Server, SingleStore, SAP), archivos y documentos (SharePoint, SFTP, Excel, CSV, JSON), fuentes externas y APIs (REST, ArcGIS, Survey123, web) y federación hacia Oracle DWH / Azure Synapse con Lakehouse Federation.

  2. 2

    Azure Databricks (plataforma central)

    Contenedor principal donde ocurre la ingeniería de datos, el gobierno y la IA. Agrupa ingesta, procesamiento, Unity Catalog / AI Gateway, capa Medallion, serve y la seguridad transversal.

  3. 3

    Ingesta

    Entrada de datos al lakehouse con Databricks Ingestion (Auto Loader, Jobs, Notebooks), API Endpoints REST, conectores (Oracle, SAP, SharePoint) e integración Event Hubs / Azure Data Factory para streaming y batch.

  4. 4

    Procesamiento (Pipelines & Orquestación)

    Motor de transformación y modelado: Workflows & Jobs ETL/ELT, Notebooks (PySpark, SQL, Python, R), Delta Live Tables, AutoML / MLflow y Data Science & GenAI (RAG, features, embeddings, vector search).

  5. 5

    Gobierno y Datos (Unity Catalog + AI Gateway)

    Gobierno de datos con catálogos, schemas, tablas, volúmenes, lineage, permisos, calidad y RLS/CLS. Gobierno de IA con modelos, endpoints, agentes, guardrails y trazabilidad. Capa Medallion: Bronze (Raw) → Silver (Limpio) → Gold (Outputs) → Consumption.

  6. 6

    Serve / Output

    Capa de entrega hacia el negocio: Power BI, Databricks Apps, Agents y Apps / APIs para consumo externo o embebido.

  7. 7

    Usuario Final

    Quién consume el valor: usuario de negocio (Q&A, reportes, decisiones), analista (exploración y self-service), áreas corporativas (Sales, HR, Finance, Supply Chain) y procesos human-in-the-loop con aprobación y control.

  8. 8

    Seguridad y Gobierno Transversal

    Capa horizontal dentro de Databricks: Microsoft Entra ID (SSO/MFA), RLS/CLS, secretos y credenciales con Azure Key Vault, auditoría y lineage end-to-end, y network security (Private Link, VNets, NSGs, IP whitelisting).

  9. 9

    Monitoreo y Operación (Azure)

    Servicios fuera de Databricks que sostienen la operación: Azure Monitor, Log Analytics, Azure DevOps (CI/CD), alertas (Email/Teams/SMS), Cost Management, Backups & DR, Azure Policy / Defender y auditoría.

  10. 10

    Principios Arquitectónicos

    Guías de diseño: Seguridad por Diseño (Zero Trust y mínimo privilegio), Gobierno de Datos, Escalabilidad serverless/elástica, Observabilidad, IA Responsable (guardrails y evaluaciones) y Valor de Negocio con datos confiables para decidir.

Herramientas

Qué usamos y para qué

Componentes del ecosistema Microsoft y Databricks que combinamos según el caso de uso.

Azure

Azure Data Factory

Orquestación de pipelines de ingesta y transformación batch/near-real-time desde sistemas origen hacia el lake.

Azure

Azure Storage Account

Data Lake Gen2 como landing y capas Bronze/Silver: almacenamiento escalable, seguro y listo para Spark.

Databricks

Azure Databricks

Lakehouse Medallion, Delta Lake, Genie Spaces, ML y agentes RAG para analítica avanzada e IA.

Microsoft

Power BI

Modelos semánticos, tableros ejecutivos y consumo self-service sobre capas Gold gobernadas.

Azure

Logic Apps

Integraciones event-driven, notificaciones y conectores empresariales sin fricción.

Microsoft

Power Platform

Power Apps, Power Automate y Power Pages para apps operativas y automatización de procesos.

Microsoft

Microsoft Fabric

Analítica unificada, OneLake y workloads de ingeniería/BI cuando el cliente apuesta por Fabric.

Azure

Azure AI Foundry

Modelos, RAG y orquestación de agentes con control, trazabilidad y despliegue empresarial.

Microsoft

Copilot Studio

Agentes conversacionales en Teams y Microsoft 365 con gobernanza y acciones de negocio.
